# ADR-0004: 動画配信に Mux を使う

- ステータス: 提案
- 日付: 2026-11-17

## 背景

講師がブラウザから大きな動画ファイル（数GB）をアップロードし、受講者がスマホ回線でも快適に視聴できる必要がある。購入者以外に再生されないようにしたい。エンコードや配信の基盤を自前で運用する余力はない。

## 選択肢

| 案 | 長所 | 短所 |
| --- | --- | --- |
| **A. Mux Video** | 直接アップロード（再開可能）、自動エンコード、署名付き再生、プレイヤー（Mux Player）、視聴データまで揃っている。開発しやすい | 従量課金の単価は自前構築より高い |
| B. Cloudflare Stream | 料金体系が分かりやすく安価な傾向。署名付き URL に対応 | 細かい制御や分析機能は Mux より少ない |
| C. S3 + MediaConvert + CloudFront | 単価が最も安い。自由度が高い | エンコードのパイプライン・署名・プレイヤーを自分で組む必要があり、運用負荷が大きい |
| D. YouTube / Vimeo の限定公開 | ほぼ無料 | 視聴の制御ができない（URL が漏れると見られる）。規約上も商用講座に不向き |

## 決定

**Mux Video** を採用する。再生ポリシーは `signed` にし、サーバーで短期の JWT を発行する。

## 結果

- 動画の処理は `modules/media` に閉じ込め、Mux 固有の ID は `video_assets` テーブルにだけ持たせる。将来 Cloudflare Stream などに移行する場合も、影響範囲をこのモジュールに限定できる。
- コストの管理: 使用量のアラートを設定する。アップロードできる解像度の上限（1080p）とファイルサイズの上限を決める。
- 料金は変更されることがあるため、Phase 2 の開始前に、想定の視聴時間で Mux と Cloudflare Stream の見積もりを比較し、この ADR を「承認」にする。
